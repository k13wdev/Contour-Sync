# Contour Sync

CLI для переноса снимка кода из внешнего Git-репозитория или локальной папки во внутренний Git-репозиторий. История внутреннего репозитория сохраняется; результат — изменения в рабочей папке для просмотра и коммита.

**Обычный JavaScript, стандартная библиотека Node.js, ноль зависимостей.** Не нужны TypeScript, сборка, `npm install`, `sudo` или права записи в каталог установки.

## Быстрый запуск

Требуются **Node.js >=22.13.0** и **Git** в `PATH`.

```bash
node bin/csync.js init
```

Заполните созданный `contour-sync.json`, затем:

```bash
node bin/csync.js doctor --project frontend
node bin/csync.js sync --project frontend
```

`sync` спросит исходную ветку, подготовит снимок, выведет список изменений и запросит `yes` перед применением. Запуск без аргументов открывает этот сценарий в интерактивном терминале; при перенаправленном вводе показывает справку.

Можно использовать `npm start -- <команда>` или установить команду `csync` через `npm link` из каталога утилиты. Это необязательно: прямой запуск через `node` работает без установки и сетевого доступа.

## Настройки JSON

`init` создаёт пример, существующий файл не перезаписывает. По умолчанию используется `contour-sync.json` в текущей папке. Другой путь: `--config /path/to/config.json` или `CONTOUR_SYNC_CONFIG`.

```json
{
  "projects": {
    "frontend": {
      "repo": "https://git.example.com/team/frontend.git",
      "targetDir": "/work/internal/frontend",
      "sourceBranch": "main",
      "preserve": [".env.production", "src/internal-config.json", ".husky"],
      "registry": {
        "from": ["https://registry.npmjs.org"],
        "to": "https://nexus.example.com/repository/npm-all"
      }
    },
    "backend": {
      "targetDir": "/work/internal/backend",
      "preserve": ["config/internal.json"]
    }
  },
  "preserve": ["dist", "coverage"],
  "tempDir": "/work/tmp"
}
```

- `projects`: проекты с уникальными именами из букв, цифр, `.`, `_` и `-`.
- `repo`: Git URL или путь к Git-репозиторию; необязателен при использовании `--from`. Локальный путь к Git-источнику лучше указывать абсолютным.
- `targetDir`: корень существующего внутреннего Git-репозитория с хотя бы одним коммитом. Относительный путь вычисляется от файла настроек.
- `sourceBranch`: исходная ветка, по умолчанию `main`. Можно переопределить через `--source`.
- `preserve`: общие и проектные правила объединяются. Точный путь с `/` действует от корня; одиночное имя действует на любой глубине. Каталог сохраняется целиком. Используйте `/` и на Windows. Glob-шаблоны не поддерживаются и считаются ошибкой.
- `registry`: необязательная замена адресов npm-реестра, отдельно для каждого проекта.
- `tempDir`: существующая папка для снимков и планов; относительный путь вычисляется от настроек.

Неизвестные поля и некорректные значения отклоняются с ошибкой, чтобы опечатки в настройках не меняли поведение молча. YAML не используется: JSON читается встроенными средствами Node.js.

Встроенная защита: `.git`, `.env`, `.env.local`, `.npmrc`, `.vscode`, `.idea`, `node_modules`. Их нельзя перезаписать или удалить через обычный план. `.git` защищён на любой глубине и независимо от регистра. Остальные правила чувствительны к регистру. Другие файлы `.env.*` добавьте в `preserve` явно.

Существующие локальные файлы, игнорируемые Git, автоматически сохраняются; соответствующие пути из источника тоже не копируются. Если такие файлы нужно обновлять переносом, сначала пересмотрите `.gitignore`. **Отсутствующие в источнике незащищённые файлы удаляются.**

## Просмотр и применение

Для раздельной проверки:

```bash
node bin/csync.js plan --project frontend --source release/1.2
# Команда выведет абсолютный путь к plan.json.
node bin/csync.js diff --plan /path/to/plan.json
node bin/csync.js apply --plan /path/to/plan.json
```

`plan` не меняет целевой репозиторий. Он создаёт отдельную папку со снимком и JSON-манифестом. `diff` показывает содержимое изменений через `git diff --no-index`; внешние diff-программы и textconv отключены.

`apply` — явная команда применения, дополнительного подтверждения не запрашивает. Перед записью повторно проверяются ветка, HEAD, содержимое файлов и целостность снимка SHA-256. При изменениях после создания плана нужно подготовить новый.

Утилита **не переключает ветки**. Подготовьте целевую ветку самостоятельно:

```bash
git -C /work/internal/frontend switch -c import/frontend-update
node bin/csync.js plan --project frontend --target import/frontend-update
```

`--target` проверяет ожидаемую текущую ветку. Это позволяет не переключать рабочую папку неожиданно и не переносить локальные изменения между ветками.

Предварительный просмотр через короткий сценарий:

```bash
node bin/csync.js sync --project frontend --dry-run
```

## Изолированные контуры

Если внешний Git недоступен из внутреннего контура, подготовьте и перенесите полную папку проекта разрешённым у вас способом:

```bash
node bin/csync.js plan --project backend --from /work/import/backend
node bin/csync.js diff --plan /path/to/plan.json
node bin/csync.js apply --plan /path/to/plan.json
```

`--from` работает с каталогом, а не с архивом. `.git` источника не переносится. Утилита не распаковывает архивы и не выполняет код из снимка. Проверьте, что каталог содержит полный проект: неполный снимок будет означать удаление отсутствующих незащищённых файлов. Полностью пустой источник отклоняется.

## Временные файлы и permission denied

Утилита не создаёт временный клон в `src` или рядом со своими исходниками. Приоритет выбора временной папки:

1. `--temp-dir`;
2. `CONTOUR_SYNC_TMP_DIR`;
3. `tempDir` в JSON;
4. системный временный каталог `os.tmpdir()`.

```bash
node bin/csync.js doctor --project frontend --temp-dir /work/tmp
node bin/csync.js sync --project frontend --temp-dir /work/tmp
```

Папка должна существовать и быть доступна для записи. Не размещайте планы внутри источника или целевого проекта. Для постоянного хранения укажите новую папку плана:

```bash
node bin/csync.js plan --project frontend --output /work/transfers/frontend-2026-11-16
```

Родитель `/work/transfers` должен существовать; сам каталог плана создаётся утилитой и не должен уже существовать.

**Планы и резервные копии сохраняются для просмотра и восстановления.** В системном временном каталоге их может удалить ОС. Для важных переносов используйте `--output` вне временного каталога. После проверки и коммита удалите папку плана вручную. Она содержит исходный код и резервную копию; корневой каталог создаётся с правами `0700`, JSON-файлы — `0600` на POSIX.

## Резервные копии и восстановление

Перед первой записью `apply` создаёт и проверяет копию управляемых файлов. Путь выводится **до начала изменений**.

```bash
node bin/csync.js restore --backup /path/to/backup-XXXXXX/backup.json
```

При обычной ошибке применения выполняется попытка автоматического восстановления. `Ctrl+C`/`SIGTERM` во время применения обрабатываются с попыткой восстановления. При `SIGKILL`, падении ОС или потере питания автоматическое завершение невозможно: сохраняются резервная копия и маркер блокировки.

Для восстановления после аварии:

1. Убедитесь, что прежний процесс contour-sync завершён.
2. Если команда сообщает о блокировке, проверьте PID в указанном `contour-sync.lock` и удалите **только этот** оставшийся файл блокировки.
3. Выполните `restore --backup ...`.

Восстановление останавливается, если сменились ветка/HEAD или обнаружены последующие изменения файлов / staged изменения в Git-индексе. Содержимое резервной копии находится в соседнем каталоге `snapshot` и остаётся доступно для ручного восстановления. Защищённые файлы и Git-индекс не входят в откат. Права обычных файлов нормализуются до `0644`, исполняемых — до `0755`; ACL, расширенные атрибуты и исходные timestamps не переносятся.

На время применения не редактируйте проект и не запускайте другие команды, меняющие рабочую папку. Блокировка защищает от второго contour-sync, но не блокирует редактор или Git. Применение выполняется по файлам; это не атомарная транзакция всей файловой системы.

## Nexus

Меняются только значения `resolved` в корневом `package-lock.json`, начинающиеся с настроенного адреса реестра и `/`. Посторонние строки, похожие домены и `integrity` остаются прежними. Преобразование выполняется в снимке до применения.

`npm install` и lifecycle scripts автоматически не запускаются. Проверку зависимостей выполняйте отдельно после просмотра результата, с внутренней `.npmrc`, например:

```bash
npm ci --ignore-scripts
```

Это отдельная команда, она требует доступа к Nexus и меняет `node_modules`. Если Nexus отдаёт другие байты пакета, сохранённый `integrity` выявит несовпадение; утилита не подменяет хеши, чтобы скрыть такую ошибку.

## Скрипты и диагностика

```bash
node bin/csync.js projects
node bin/csync.js doctor --project frontend --json
node bin/csync.js sync --project frontend --source main --yes --json
```

`--yes` относится только к `sync`. В неинтерактивном запуске применение через `sync` требует `--yes`; без него сохраняется план и возвращается ошибка с инструкцией. `--json` отключает вопросы и выдаёт результат в stdout. Сообщение о создании резервной копии и ошибки идут в stderr. Коды завершения: `0` — успех, `1` — ошибка, `130`/`143` — прерывание сигналом.

`doctor` проверяет конфигурацию, Git, состояние целевого репозитория, доступ к каталогам и возможность создания временных файлов. Сетевой доступ и учётные данные Git/Nexus он не проверяет. Git-клонирование использует настроенные SSH-ключи/credential helper; интерактивный HTTP-запрос пароля отключён. Таймаут Git-команд — 120 секунд.

## Ограничения

- Не поддерживаются символические ссылки, специальные файлы и целевые submodules; перенос останавливается до применения.
- Источник Git с submodules нужно предварительно подготовить целиком и передать через `--from`.
- В цели недопустимы detached HEAD, незавершённые merge/rebase и файлы с `skip-worktree`/`assume-unchanged`.
- Поддерживается перенос ветки Git, а не произвольного commit SHA или архива.
- Формат JSON новый; прежний `config/settings.json` автоматически не мигрируется.

## Разработка

```bash
npm test
npm run check
```

Тесты используют встроенный `node:test` и настоящие временные локальные Git-репозитории. Сеть и установка пакетов не нужны.

```text
bin/csync.js                CLI, вопросы, аргументы, вывод
lib/config.js                  JSON, валидация, правила сохранения
lib/git.js                     Git без shell-интерполяции
lib/files.js                   Сканирование, SHA-256, файловые операции
lib/sync.js                    Планы, снимки, diff, backup, apply, restore
config/contour-sync.example.json   Пример настроек
test/sync.test.js              Интеграционные проверки
```
